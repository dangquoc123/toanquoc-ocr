# Charset & syllable data

## `syllables.txt`
Generated by `python scripts/build_charset.py`. One NFC syllable per line.

It is produced from a **phonotactic table** (onset × rime × tone + spelling
rules) in `vnocr/charset/syllables.py`. The generator intentionally
**over-generates** — some onset+rime pairs it allows never actually occur. For a
*validity filter* (Design §5.1) that is the safe direction: a superset never
rejects a real word. The current table yields ~18.9k entries; the true inventory
is ~7k (§5.1).

### Getting the tight ~7k inventory (recommended for production)
Intersect the generated set with a **corpus frequency list**, which also gives
you the unigram priors the noisy-channel corrector wants (§5.2, §6.3):

```bash
# pseudo: keep only generated syllables that actually occur in a real corpus
python - <<'PY'
from vnocr.charset import generate_syllables
gen = set(generate_syllables())
seen = set()  # fill from your tokenised Wikipedia+news corpus
# ... tokenise corpus, lowercase, add tokens to `seen` ...
tight = sorted(gen & seen)
open("data/charset/syllables.txt", "w").write("\n".join(tight) + "\n")
PY
```

## Base / modifier / tone factors
The factorised head (Lever 1, §3.2) does **not** use `syllables.txt` directly;
it derives its classes from `vnocr.charset.default_charset()`:
- base: ~102 classes (a-z, A-Z, 0-9, punctuation)
- modifier: 5 (none, breve, circumflex, horn, đ-stroke)
- tone: 6 (none, sắc, huyền, hỏi, ngã, nặng)

`syllables.txt` is used by the **post-processor** (trie + noisy channel + LM).
